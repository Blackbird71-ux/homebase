============================================================================
RESPONSIVE EDITOR LAYOUTS PLAN
HomeBase — Dynamic Layout for Large Screens + Mobile
============================================================================

1. PROBLEM STATEMENT
---------------------------------------------------------------------------
On larger screens (1920px+, >27" monitors), HomeBase layouts remain 
constrained to a single-column content area with fixed-width sidebars.
Users must scroll vertically on pages with dense data (bills, transactions,
meal plan) because the application does not take advantage of available 
horizontal space. Mobile is fine, desktop is under-optimized.


2. DESIGN GOALS
---------------------------------------------------------------------------
A. Dynamic content density — larger screens show more columns, wider tables,
   and side-by-side panels automatically
B. Viewport-aware — content fills available height to minimize scrolling
C. Mobile-first — all changes degrade gracefully down to 320px viewports
D. No horizontal scroll — content never overflows horizontally
E. Progressive enhancement — more detail becomes visible as space allows


3. DENSITY TIERS
---------------------------------------------------------------------------
Tier        Width Range     Columns    Description
------      -----------     -------    -----------
compact     < 640px         1          Mobile phone
normal      640 - 1023px    1-2        Tablet portrait
spacious    1024 - 1535px   2-3        Tablet landscape / small desktop
wide        >= 1536px       3-4+       Large desktop / ultrawide

4.3 PHASE 3: Page-Level Layout Improvements
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

4.3.1 BILLS PAGE (src/app/(app)/finance/bills/page.tsx)
------

Current problem: gridTemplate is fixed. Category columns always 6.5rem,
action buttons cramped, no expansion on wide screens.

Solution:
- Replace fixed gridTemplate with computed function based on tier
- Category columns: 6.5rem (compact/normal) -> 7rem (spacious) -> 8rem (wide)
- Description column: 1fr -> 1.5fr -> 2fr
- Actions column: 8.5rem -> 10rem -> 12rem
- On wide: show more metadata inline (entity badge, tax classification)

4.3.2 TRANSACTIONS PAGE
------

- Show more columns on spacious+ (entity, category path, notes)
- Table font scales with tier
- Keep current minimal columns on compact/normal

4.3.3 MEAL PLAN (src/components/meal-plan/MealPlanGrid.tsx)
------

Current problem: Days stack vertically in single column. Only 4-5 days
visible on a 27" monitor.

Solution - multi-column day grid:
- compact:   1 column (no change)
- normal:    1 column (no change)
- spacious:  2 columns (reduces scroll by 50%)
- wide:      3 columns (shows 10+ days at once)

Uses CSS grid: grid-cols-1 / grid-cols-2 / grid-cols-3

4.3.4 CALENDAR (src/components/calendar/CalendarView.tsx)
------

Week view:
- spacious+: add side panel showing event details for selected day
- wide: show optional "Agenda" sidebar with scrollable event list
- Hour column widths increase proportionally

Month view:
- spacious+: show 3+ events per cell with full titles
- wide: show 5+ events per cell

4.3.5 NOTES (src/app/(app)/notes/NotesClient.tsx)
------

- spacious: 2-column card grid with auto-fill
- wide: 3-column card grid with preview content
- compact/normal: 1 column (no change)

CSS: grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))

4.3.6 LISTS (src/app/(app)/lists/ListsClient.tsx)
------

- spacious+: ListSelector becomes sidebar panel (220px) beside list content
- compact/normal: stacked (no change)

4.3.7 DASHBOARD (src/components/dashboard/DashboardGrid.tsx)
------

- wide: default new cards to 50% width instead of 100%
- wide: allow cards to be up to 33% width (3-column layout)
- spacious: default to half-width cards

9. KEY PRINCIPLE: PROGRESSIVE ENHANCEMENT
---------------------------------------------------------------------------
Every change follows this pattern:
1. Mobile layout stays exactly as-is (already functional)
2. At each breakpoint, add/expand content horizontally
3. Content is never removed at larger sizes — only added
4. All scrollable containers maintain proper overflow-y-auto with min-h-0
5. No horizontal scrollbars are introduced
