# Homebase — Design Spec
**Date:** 2026-04-16  
**Status:** Approved

---

## 1. Vision

Homebase is a private, self-hosted family management platform running as a Docker container on a Synology NAS. It replaces Cozi as the primary family hub, providing a shared calendar, shopping/todo lists, recipe library, and meal planner — all in one fullscreen app.

### Core Principles
- **Family-scoped:** All data belongs to a single `Family` record shared by all members
- **Fullscreen-first:** Designed as 100vh/vw — feels like a native app, not a webpage
- **Settings-first:** All appearance and behaviour preferences stored in the database, not hardcoded
- **Local-first auth:** Email/password only (no OAuth), simple and private
- **Standalone deployment:** Dockerised Next.js standalone build, `/data` volume for persistence

## 3. Layout & Navigation

### Fullscreen Shell
The app occupies the full viewport (`100vw`, `100vh`). No page-level scroll — each section manages its own scrollable area internally.

### Persistent Left Sidebar
Always visible. Contains:
```
🏠 HOMEBASE          ← app name / logo

🏡 Home              ← dashboard (default landing page)
📅 Calendar
✅ Lists
🍳 Recipes
📆 Meal Plan

─────────────────
⚙️ Settings          ← pinned to bottom
```
Active route is highlighted. Settings is always at the bottom, separated by a divider.

### Home Dashboard
2×2 grid of summary cards:

| Card | Content |
|------|---------|
| 📅 Upcoming | Next 3–5 events from the family calendar |
| 🍽️ Tonight's Dinner | Today's meal plan entry (recipe name + link) |
| 🛒 Shopping List | Item count + first few items from active shopping list |
| ✅ Todo | Count of tasks due today + first few items |

Each card is clickable and navigates to the full section.

## 4. Authentication & Family Model

### Registration Flow
1. First user registers → creates the `Family` record, enters family name, assigned `role: admin`
2. Subsequent users register with an invite code generated by the admin (Settings → Account)
3. All users share the same family's data

### Roles
| Role | Permissions |
|------|-------------|
| `admin` | Full access: manage users, all settings, run Cozi import, delete data |
| `member` | Read/write all family data (events, lists, recipes, meal plans); cannot manage users or run imports |

### Auth Implementation
- NextAuth v5 `CredentialsProvider` — email + bcrypt-hashed password
- Session via JWT cookies
- All routes protected; unauthenticated users redirected to `/login`

## 5. Database Schema

```prisma
model Family {
  id             String       @id @default(cuid())
  name           String
  umamiScriptUrl String?      // e.g. https://umami.yourdomain.com/script.js
  umamiSiteId    String?      // Umami website ID
  users          User[]
  events         Event[]
  lists          List[]
  recipes        Recipe[]
  mealPlans      MealPlan[]
  coziImports    CoziImport[]
}

model User {
  id            String   @id @default(cuid())
  email         String   @unique
  password      String   // bcrypt hashed
  name          String
  role          String   @default("member") // "admin" | "member"
  familyId      String
  family        Family   @relation(fields: [familyId], references: [id])

  // Settings-first fields
  theme         String   @default("modern") // light | dark | system
  fontSize      String   @default("base")   // sm | base | lg
  weekStartsOn  Int      @default(0)         // 0=Sunday, 1=Monday
  uiPreferences Json?
}

model Event {
  id          String   @id @default(cuid())
  title       String
  description String?
  start       DateTime
  end         DateTime
  isAllDay    Boolean  @default(false)
  category    String?  // Medical | School | Social | Work | Other
  color       String?
  createdBy   String   // userId
  familyId    String
  family      Family   @relation(fields: [familyId], references: [id])
  createdAt   DateTime @default(now())
}

model List {
  id        String     @id @default(cuid())
  name      String
  type      String     // "SHOPPING" | "TODO"
  isActive  Boolean    @default(true)
  items     ListItem[]
  familyId  String
  family    Family     @relation(fields: [familyId], references: [id])
  createdAt DateTime   @default(now())
}

model ListItem {
  id          String   @id @default(cuid())
  content     String
  isCompleted Boolean  @default(false)
  category    String?  // Dairy | Produce | Meat | etc.
  sortOrder   Int      @default(0)
  createdBy   String   // userId
  listId      String
  list        List     @relation(fields: [listId], references: [id])
  createdAt   DateTime @default(now())
}

model Recipe {
  id           String     @id @default(cuid())
  title        String
  description  String?
  ingredients  Json       // string[]
  instructions Json       // string[]
  image        String?
  sourceUrl    String?
  prepTime     Int?       // minutes
  cookTime     Int?       // minutes
  servings     Int?
  tags         String[]
  createdBy    String     // userId
  familyId     String
  family       Family     @relation(fields: [familyId], references: [id])
  mealPlans    MealPlan[]
  createdAt    DateTime   @default(now())
}

model MealPlan {
  id        String   @id @default(cuid())
  date      DateTime
  mealType  String   @default("dinner") // breakfast | lunch | dinner | snack
  recipeId  String?
  recipe    Recipe?  @relation(fields: [recipeId], references: [id])
  note      String?  // free-text for non-recipe meals (e.g. "Takeaway")
  familyId  String
  family    Family   @relation(fields: [familyId], references: [id])
}

model CoziImport {
  id         String   @id @default(cuid())
  importedAt DateTime @default(now())
  importedBy String   // userId (admin only)
  eventCount Int      @default(0)
  listCount  Int      @default(0)
  itemCount  Int      @default(0)
  notes      String?
  familyId   String
  family     Family   @relation(fields: [familyId], references: [id])
}
```

## 6. Feature Modules

### 6.1 Calendar
- Month view (default) and week view toggle
- Create / edit / delete events
- Event categories with colour coding
- Events display on Home dashboard (next 3–5)

### 6.2 Lists
- Two types: **Shopping** and **Todo**
- Multiple lists supported (e.g. "Weekly Shop", "Costco Run")
- Shopping list: items grouped by category (Dairy, Produce, Meat, etc.), tap to mark complete
- Todo list: ordered items, due dates optional, tap to mark complete
- Active shopping list item count shown on Home dashboard

### 6.3 Recipes
- Manual entry form (title, ingredients, instructions, tags, image upload)
- URL scraper: paste a recipe URL, `cheerio` extracts ingredients + instructions
- Search and filter by tags
- Recipe detail page with print-friendly view

### 6.4 Meal Planner
- Weekly grid view (Mon–Sun or Sun–Sat based on `weekStartsOn` setting)
- Assign a recipe or free-text note to any meal slot
- Tonight's meal shown on Home dashboard
- Future: "Add ingredients to shopping list" button from meal plan

### 6.5 Settings
Tab-based settings page (pattern from Memories app):

| Tab | Contents |
|-----|----------|
| **Account** | Name, email, password change, invite code generation (admin), family name (admin) |
| **Appearance** | Theme (light/dark/system), font size, week start day |
| **Integrations** | Cozi import tool (admin only), Umami site ID + script URL |
| **Data** | Export family data (JSON), import history, danger zone (delete account) |

## 7. Integrations

### 7.1 Cozi — One-Time Import (Admin Only)
**Location:** Settings → Integrations → Import from Cozi

**What is imported:**
- Calendar events (all future + last 12 months)
- All lists and their items

**What is NOT imported:**
- Recipes (Homebase's recipe system is used from scratch)

**Import method:**
- User exports their Cozi data (Cozi provides a `.ics` file for calendar, and optionally list data)
- Admin uploads the file(s) via the import UI
- Parser maps Cozi fields to Homebase schema
- Results shown: "X events and Y list items imported"
- Import log saved to `CoziImport` table with timestamp and counts
- Import can be re-run at any time (admin only); previous import history visible in Settings → Data

**Supported formats:**
- `.ics` (iCalendar) for calendar events
- Cozi CSV/JSON export for lists (if available; otherwise manual re-entry)

### 7.2 Umami Analytics — Passive Tracking
**Location:** Settings → Integrations → Umami

**Configuration (stored on the `Family` record — applies to all members):**
- Umami script URL (e.g. `https://umami.yourdomain.com/script.js`) → `Family.umamiScriptUrl`
- Umami website ID → `Family.umamiSiteId`

**Behaviour:**
- Once configured, the Umami `<script>` tag is injected into the app's root layout
- Tracks page views and navigation automatically
- No ongoing sync — purely passive once set up
- Admin only can configure; applies to all family members

## 8. Docker Deployment

### Container
- Base: `node:22-alpine`
- Multi-stage build: deps → builder → runner
- Standalone Next.js output
- `/data` volume for SQLite database

### Environment Variables
```bash
DATABASE_URL=file:/data/homebase.db
NEXTAUTH_SECRET=<random string>
NEXTAUTH_URL=https://homebase.yourdomain.com
ENCRYPTION_KEY=<32-byte base64 key>   # for any future sensitive fields
```

### Entrypoint
- Runs `prisma migrate deploy` on startup
- Creates `/data` directory if missing
- Starts Next.js server on port 3000

### docker-compose.yml (target)
```yaml
version: "3.8"
services:
  homebase:
    image: homebase:latest
    ports:
      - "3001:3000"
    volumes:
      - ./data:/data
    environment:
      - DATABASE_URL=file:/data/homebase.db
      - NEXTAUTH_SECRET=${NEXTAUTH_SECRET}
      - NEXTAUTH_URL=${NEXTAUTH_URL}
      - ENCRYPTION_KEY=${ENCRYPTION_KEY}
    restart: unless-stopped
```

## 10. Out of Scope
- No mobile app (responsive web only)
- No recurring events (v1; can be added later)
- No push notifications
- No recipe import from Cozi (start fresh)
- No ongoing Cozi sync — import is one-time only
- No Google OAuth or third-party login
