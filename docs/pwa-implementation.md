# PWA (Progressive Web App) Implementation

## Overview

Homebase now supports Progressive Web App (PWA) features, allowing users to install the application on their devices for a native app-like experience. This includes home screen installation, push notification support, and basic offline caching.

## Files Created

### `src/app/manifest.ts`
Dynamic web app manifest generated by Next.js. Provides the browser with metadata about the application including:
- App name and description
- Display mode (`standalone` for full-screen app experience)
- Theme and background colors
- Icon references (192x192 and 512x512)
- Orientation and category metadata

### `public/sw.js`
Service worker that handles:
- **Push notifications**: Receives and displays push notifications from the server
- **Notification clicks**: Opens the app when a notification is clicked
- **Basic offline caching**: Network-first strategy for navigation, cache-first for static assets
- **Cache management**: Cleans up old caches on activation

### `public/icon-192x192.png` and `public/icon-512x512.png`
PWA icons copied from the project root (`icon-192.png` and `icon-512.png`) for use in the manifest and as notification icons.

## Files Modified

### `src/app/layout.tsx`
Added to the exported `metadata` object:
- `manifest: '/manifest.webmanifest'` — links the web app manifest
- `theme-color: '#000000'` — sets the browser theme color
- Apple-specific meta tags for iOS home screen support:
  - `mobile-web-app-capable: 'yes'` (replaces deprecated `apple-mobile-web-app-capable`)
  - `apple-mobile-web-app-status-bar-style: 'default'`
  - `apple-mobile-web-app-title: 'Homebase'`

### `next.config.ts`
Added security headers via the `async headers()` function:
- **Global headers** (applied to all routes):
  - `X-Content-Type-Options: nosniff` — prevents MIME type sniffing
  - `X-Frame-Options: DENY` — protects against clickjacking
  - `Referrer-Policy: strict-origin-when-cross-origin` — controls referrer info
- **Service worker headers** (applied to `/sw.js`):
  - `Content-Type: application/javascript; charset=utf-8`
  - `Cache-Control: no-cache, no-store, must-revalidate` — prevents caching
  - `Content-Security-Policy: default-src 'self'; script-src 'self'`

## How to Test

1. **Build the application**: `npm run build`
2. **Start the production server**: `npm start`
3. **Open in a browser** (Chrome, Edge, or Safari on iOS 16.4+)
4. **Verify the manifest**: Open DevTools → Application → Manifest to see the PWA manifest loaded
5. **Install the PWA**: Look for the install icon in the address bar (Chrome/Edge) or use "Add to Home Screen" (Safari iOS)
6. **Test offline**: After visiting pages, go offline and verify cached content loads

## Docker Deployment

The Dockerfile already copies the `public/` directory to the final image, so all PWA assets (icons, service worker) are included automatically. No changes to the Dockerfile or entrypoint were needed.

## Known Limitations

- **Push notifications**: Requires VAPID keys and a server-side subscription store to be fully functional. The service worker handles push events, but the subscription management and notification sending logic would need to be implemented separately.
- **Offline support**: Basic caching is implemented, but full offline functionality (e.g., offline form submissions, data sync) would require additional work with libraries like Serwist or Workbox.
- **iOS**: iOS Safari supports PWA installation from iOS 16.4+, but some features (like push notifications) have limited support.
